# CamWall

Мінімалістична вебвідеостіна для RTSP-камер на Debian / Armbian. FFmpeg читає RTSP і передає MPEG-TS через WebSocket, а браузер відтворює потік через mpegts.js / Media Source Extensions.

## Можливості

- Адаптивна сітка камер, пошук, обрані камери та повноекранний режим браузера.
- Додавання/редагування/видалення камер через вебналаштування.
- Окремі файли конфігурації: `playlist.json` для камер і `settings.json` для налаштувань інтерфейсу.
- Один FFmpeg-процес на камеру, спільний для кількох глядачів.
- Серверне зменшення роздільності/FPS і перекодування в H.264 з обмеженням бітрейту.
- Перепідключення після розриву, systemd-сервіс, без Docker, БД або MediaMTX.

## Встановлення

На Debian / Armbian:

\`\`\`bash
git clone https://github.com/ZoNier/camwall.git
cd camwall
sudo bash install.sh
sudo systemctl start camwall
sudo systemctl status camwall
\`\`\`

Відкрий \`http://IP_СЕРВЕРА:8080\`. Після інсталяції робочий конфігураційний файл: \`/opt/camwall/playlist.json\`.

## Оновлення з Git

Після першого встановлення залиш Git-клон проєкту на сервері. Для отримання останніх змін виконай команду **від звичайного користувача, який володіє клоном**, не через `sudo`:

```bash
cd ~/camwall
bash update.sh
```

Скрипт перевіряє GitHub і завершується без перезапуску, якщо нових комітів немає. Якщо зміни є — виконує `git pull --ff-only`, встановлює файли, оновлює залежності Python і перезапускає сервіс. Він не копіює робочі `playlist.json` та `settings.json` з репозиторію, тому камери й налаштування інтерфейсу зберігаються. Незакомічені зміни в інших файлах клону зупинять оновлення.

Для ручного запуску без інсталятора:

\`\`\`bash
sudo apt install python3-venv ffmpeg
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
uvicorn app:app --host 0.0.0.0 --port 8080
\`\`\`

## Конфігурація

Робочі конфігураційні файли зберігаються окремо в `/opt/camwall/`:

- `playlist.json` — **лише список камер** та їхні RTSP URL. Початковий приклад у репозиторії: `playlist.example.json`.
- `settings.json` — параметри вебінтерфейсу. Початковий шаблон у репозиторії: `settings.example.json`.

Приклад `playlist.json`:

```json
{
  "cameras": [
    {
      "name": "CAM 1",
      "url": "rtsp://USER:PASSWORD@192.168.1.101/stream1",
      "favorite": false,
      "country_name": null,
      "enabled": true
    }
  ]
}
```

Приклад `settings.json`:

```json
{
  "grid_columns": 4,
  "theme": "dark",
  "autoplay": true,
  "low_latency": true,
  "reconnect_seconds": 3,
  "stream_audio": false
}
```

Робочі файли `playlist.json` і `settings.json` ігноруються Git. Оновлення застосунку не замінює їх. Якщо стара версія зберігала параметри інтерфейсу й камери разом у `playlist.json`, нова версія перенесе налаштування в `settings.json`, а список камер залишить у `playlist.json`.

## Безпека

**Ця версія не має автентифікації.** API налаштувань повертає RTSP URL, зокрема облікові дані, браузеру для редагування. Не виставляй порт 8080 в інтернет. Обмеж доступ firewall-ом до довіреної LAN або додай авторизований reverse proxy. Не коміть реальні URL/паролі камер у публічний Git. У репозиторії \`playlist.json\` містить лише демонстраційні адреси.

## Оптимізація для багатьох камер

CamWall самостійно обробляє кожен вхідний RTSP-потік на сервері. Для відеостіни FFmpeg за замовчуванням зменшує його до 640×360, 10 FPS, H.264 (`libx264`, `ultrafast`, `zerolatency`) із цільовим бітрейтом 500 kbit/s і maxrate 600 kbit/s. У конфігурації кожної камери потрібен лише один `url`.

**Важливо:** серверне перекодування навантажує CPU. На слабких ARM-пристроях 8–16 потоків можуть бути завеликим навантаженням. У такому випадку варто налаштувати апаратне кодування (якщо воно доступне) або зменшити кількість одночасних потоків/FPS/роздільність.

## Затримка, кодеки та ресурси

MPEG-TS через WebSocket уникає сегментної затримки HLS, але затримка менш як 1 секунда не гарантується: вона залежить від камери, GOP, мережі, браузерного буфера та кодека. H.264 зазвичай має найкращу сумісність; підтримка H.265/HEVC у браузерах обмежена. Якщо можливо, налаштуй H.264 субпотік на камері. Для 8–16 камер перевір CPU, мережеву пропускну здатність і стабільність саме на своєму обладнанні.

Для першого відкриття сторінки потрібен доступ до CDN \`cdn.jsdelivr.net\` для завантаження mpegts.js.

## Діагностика

\`\`\`bash
curl http://127.0.0.1:8080/health
sudo journalctl -u camwall -f
ffmpeg -hide_banner -rtsp_transport tcp -i 'rtsp://USER:PASS@CAMERA/PATH' -t 5 -f null -
\`\`\`

Не вставляй RTSP URL із паролем у публічні логи чи звернення до підтримки.
