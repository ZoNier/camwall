# CamWall

Мінімалістична вебвідеостіна для RTSP-камер на Debian / Armbian. CamWall постійно приймає RTSP-потоки на сервері та ретранслює їх браузерам без перекодування відео.

## Як працює відео

- Під час запуску CamWall створює по одному постійному FFmpeg-процесу для кожної увімкненої камери.
- FFmpeg використовує `-c:v copy`: відео не декодується, не масштабується та не перекодовується.
- FFmpeg формує HLS-плейлист та MPEG-TS-сегменти на диску; браузери отримують їх через авторизовані HTTP-запити.
- Підключення браузера не запускає новий FFmpeg і не створює нового RTSP-з'єднання до камери.
- Кожна камера має власний HLS-плейлист із коротким ковзним вікном; усі глядачі використовують ті самі сегменти.
- При втраті RTSP-з'єднання CamWall автоматично перепідключається.
- Кодек, ширина та висота визначаються через ffprobe; стан можна переглянути через `/health` або `/api/streams`.

**Важливо:** сервер більше не перекодовує відео. Тому відтворення залежить від підтримки кодека конкретним браузером і його MSE та підтримки контейнера/кодека. H.264 зазвичай має найкращу сумісність. H.265/HEVC може працювати не в усіх браузерах та операційних системах. У разі несумісності CamWall покаже помилку, а не буде непомітно навантажувати сервер перекодуванням.

Коли live-відео не запущене, у картці камери показується спільне кешоване JPEG-прев'ю. Воно формується одним коротким FFmpeg-завданням приблизно раз на 25–30 секунд з останнього HLS-сегмента, без додаткового RTSP-з'єднання. Останній вдалий кадр зберігається під час перепідключення камери.

## Авторизація та безпека

- Після першого встановлення створюється адміністратор `admin` з випадковим паролем. Інсталятор показує його один раз — збережи пароль.
- Пароль зберігається лише у вигляді Argon2-хешу в `/opt/camwall/auth.json` (права доступу 0600).
- Сесії зберігаються в підписаній HttpOnly cookie з SameSite=Strict: 12 годин за замовчуванням або 30 днів із прапорцем «Запам'ятати мене».
- API конфігурації, станів та HLS-потоки доступні лише після входу.
- Є обмеження спроб входу та перевірка Origin для змін і HTTP/HLS.
- У налаштуваннях можна змінити пароль адміністратора (мінімум 8 символів).

Для HTTPS за reverse proxy встанови `CAMWALL_COOKIE_SECURE=1` у `/etc/camwall/camwall.env` і перезапусти службу. Не використовуй незахищений HTTP через публічний інтернет. Для доступу ззовні застосовуй HTTPS.

Файли авторизації:
- `/opt/camwall/auth.json` — логін та Argon2-хеш пароля.
- `/etc/camwall/camwall.env` — секрет підпису сесій, права 0600.

## Можливості

- Адаптивна сітка камер, пошук, обрані камери та повноекранний режим.
- Кешовані JPEG-прев'ю та компактні власні кнопки керування відео без стандартної панелі браузера.
- Додавання, редагування та видалення камер через вебналаштування.
- Індивідуальні параметри кожної камери: автозапуск відео та передавання аудіо.
- Є два глобальні режими буферизації: збалансований (ліміт HLS-вікно близько 8–12 с) і низької затримки (близько 3–6 с). Фактична затримка залежить від камери, GOP, мережі та декодера браузера; автозапуск можна ввімкнути для всіх камер однією дією.
- Окремі конфігураційні файли: `playlist.json` для камер і `settings.json` для інтерфейсу.
- Один постійний FFmpeg-процес на камеру, спільний для всіх глядачів.
- Передавання відео без перекодування.
- systemd-сервіс без Docker і бази даних.

## Встановлення з нуля

Потрібен Debian або Armbian із доступом до репозиторіїв пакетів та GitHub:

```bash
git clone https://github.com/ZoNier/camwall.git
cd camwall
sudo bash install.sh
```

Інсталятор встановить FFmpeg/ffprobe, Python-залежності, створить системного користувача `camwall`, Python venv, systemd-службу та запустить застосунок.

Відкрий `http://IP_СЕРВЕРА:8080`.

## Повторне встановлення

Щоб перевстановити застосунок і **зберегти список камер та налаштування**:

```bash
sudo bash /opt/camwall/uninstall.sh
sudo bash install.sh
```

Звичайне видалення залишає `/opt/camwall/playlist.json` і `/opt/camwall/settings.json`. Для повного видалення разом із конфігурацією:

```bash
sudo bash uninstall.sh --purge
```

## Оновлення

```bash
sudo bash /opt/camwall/update.sh
```

Скрипт завантажує останню версію з GitHub, оновлює Python-залежності та перезапускає службу. Робочі конфігураційні файли не перезаписуються.

## Конфігурація

Робочі файли зберігаються в `/opt/camwall/`:

- `playlist.json` — назви камер та RTSP URL. Шаблон у репозиторії: `playlist.example.json`.
- `settings.json` — налаштування вебінтерфейсу. Шаблон: `settings.example.json`.

Не додавай реальні RTSP URL та паролі до публічного репозиторію.

## Навантаження та сумісність

У режимі `-c:v copy` сервер не виконує H.264/H.265 encode/decode і не змінює роздільність чи FPS. Основне навантаження — мережевий трафік, копіювання даних і робота з HLS/HTTP. Кожна камера споживає вхідний трафік постійно, навіть коли її ніхто не переглядає.

H.264 зазвичай підтримується ширше. Підтримка H.265/HEVC у браузерах залежить від браузера, ОС, апаратного декодера та MSE. Також аудіо за замовчуванням вимкнено; якщо його ввімкнути, аудіопотік копіюється без перекодування, тому сумісність аудіокодека теж залежить від браузера.

JPEG-прев'ю генеруються окремо від live-плеєра з останнього HLS-сегмента: один кадр на камеру приблизно раз на 25–30 секунд. На клієнті прев'ю оновлюється раз на 30 секунд; запити не створюють нових RTSP-з'єднань.

## Безпека

CamWall має вбудовану авторизацію. API налаштувань передає RTSP URL та облікові дані лише авторизованій сесії. Не виставляй порт 8080 безпосередньо в інтернет; для зовнішнього доступу використовуй HTTPS.

## Діагностика

```bash
curl http://127.0.0.1:8080/health
curl http://127.0.0.1:8080/api/streams
sudo systemctl status camwall
sudo journalctl -u camwall -f
ffprobe -v error -rtsp_transport tcp -select_streams v:0 -show_entries stream=codec_name,width,height -of json 'rtsp://USER:PASS@CAMERA/PATH'
```

Не вставляй RTSP URL із паролем у публічні логи чи звернення до підтримки.
